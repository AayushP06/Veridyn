# VeriDyn: Project Rules

## What this project is

VeriDyn is a college Theory of Computation project: certified inductive
challenges built from finite automata. The user sees labelled example
sequences (accepted and rejected) of a HIDDEN regular rule, infers the rule,
and classifies new test sequences. Test sequences are generated by automata
algorithms so that no hypothesis in a fixed library H that fits the examples
can pass.

## Scope statement (must appear in UI, docs and README)

"VeriDyn certifies that no guessing strategy in a stated hypothesis class
passes the challenge. It does NOT verify that a respondent is human. Learners,
programs and language models outside that class are not covered."

## Hard rules

1. Pure Python 3.11+. Implement ALL automata algorithms yourself. No automata
   libraries. Python's `re` is allowed ONLY in tests as a differential oracle.
2. The hidden rule, its regex, its DFA and the certificate NEVER leave the
   server. API responses contain only example strings, test strings, tile data.
3. User-facing wording is fixed: "Challenge passed" / "Challenge failed". Never
   write "human", "verified" or "bot detected" in the UI or API.
4. Keep it small: no microservices, no Docker, no ML, no accounts, no paid
   services. Allowed dependencies: fastapi, uvicorn, pydantic, pytest,
   hypothesis. Anything else: ask first.
5. Every module has type hints, a docstring naming the TOC concept it
   implements, and unit tests.
6. Never silently change a language. Every construction step must pass
   differential tests against `re.fullmatch` on all strings up to length 8
   over a 3-letter alphabet.
7. Do not weaken or delete tests to make them pass.

## Domain model

- Alphabet is a parameter. Default Sigma = {C, T, S}.
- Regex syntax: literals, `|`, concatenation, `*`, `+`, `?`, `{m,n}`, `{m}`,
  `{m,}`, parentheses. Caps: regex length 80, repetition bound 6.
- DFAs are complete (explicit dead state).
- Hypothesis library H: at least 30 small DFAs built through the same pipeline:
  starts with X, ends with X, contains X, contains XX, no XX, count of X
  even/odd, count of X mod 3, length parity, length <= k, length >= k, and
  negations. H is data, not hardcoded in the certifier.
- Hidden rule family: a Boolean combination (and / or / not) of at most 2 atoms
  from H's atom set. A hidden rule must NOT be equivalent to any member of H.
- Challenge = N_ex labelled examples shown (default 3 accepted + 3 rejected,
  length 2 to 6) + k test strings (default k = 6, balanced 3 valid / 3 invalid,
  length <= 8). Pass = all test strings classified correctly.
- Certificate: for every h in H that is consistent with the shown examples,
  at least one test string where h and the hidden rule differ.
- A coin-flipping respondent passes a balanced k-string test with probability
  exactly 2^-k.

## Session guard defaults (configurable)

Nonce expiry 120 s, one-time use, 3 attempts per session (each attempt gets a
fresh challenge), 30 requests/min per IP, response length cap 8 symbols.

## Working style

- Use planning mode: write a short implementation plan (10 lines max) and wait
  for my approval before editing files.
- Run the tests in the terminal and show real output. Never claim tests pass
  without running them.
- If something is ambiguous, pick the simplest option, record it in
  docs/spec.md under "Decisions", and continue.
- Stay inside the task's scope. Do not touch unrelated files.
